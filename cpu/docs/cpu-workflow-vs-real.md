# 自制 CPU vs 真实 CPU 工作流程对比

## 一、真实 CPU 的完整工作栈

一台能跑贪吃蛇的真实计算机从上到下需要这些层次：

```
┌─────────────────────────────────────────┐
│  C 程序 (snake_vga.c)                    │  ← 高级语言
├─────────────────────────────────────────┤
│  编译器 (gcc) → RISC-V 汇编 → 机器码     │  ← 工具链
├─────────────────────────────────────────┤
│  操作系统 (进程调度、驱动、中断)         │  ← OS
├─────────────────────────────────────────┤
│  指令集架构 (ISA): RISC-V RV32I         │  ← CPU 与软件的接口
├─────────────────────────────────────────┤
│  微架构: 流水线、转发、缓存、分支预测    │  ← CPU 内部实现
├─────────────────────────────────────────┤
│  外设: UART、VGA、键盘控制器             │  ← I/O
├─────────────────────────────────────────┤
│  物理层: 晶体管、导线、时钟树            │  ← 硅片
└─────────────────────────────────────────┘
```

### 一条指令在真实 CPU 中的旅程

以 `sb t1, 0(t0)` （把 t1 的低字节存到 t0 指向的地址）为例：

```
1. 取指 (IF)    PC → 指令缓存 → 取出 32-bit 指令
2. 译码 (ID)    解析出: opcode=STORE, rs1=t0, rs2=t1, imm=0
3. 执行 (EX)    ALU 计算地址 = t0 + 0
4. 访存 (MEM)   地址 → 数据缓存 → 写入字节
5. 写回 (WB)    无(store 不写寄存器)
```

每个阶段 1 个时钟周期，5 条指令可同时在流水线中（经典 5 级 RISC）。

## 二、本项目 CPU 的实际实现

### 2.1 整体架构：单周期哈佛结构

```
┌──────────────────────────────────────────────────┐
│                  cpu_top.sv                       │
│                                                   │
│  ┌──────┐   ┌─────────┐   ┌──────┐   ┌─────────┐ │
│  │  PC  │──→│指令存储器│──→│ 控制 │──→│寄存器堆 │ │
│  │      │   │(insn_mem)│   │ 单元 │   │(regfile)│ │
│  └──────┘   └─────────┘   └──┬───┘   └───┬─────┘ │
│                              │            │       │
│                         ┌────┴────┐  ┌───┴─────┐ │
│                         │立即数生成│  │   ALU   │ │
│                         │(imm_gen)│  │         │ │
│                         └─────────┘  └───┬─────┘ │
│                                    地址/数据    │
│                              ┌──────┴──────────┐ │
│                              │   数据存储器     │ │
│                              │  (data_mem)     │ │
│                              │  + MMIO 路由    │ │
│                              └──────┬──────────┘ │
│                                     │            │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──┴──────┐     │
│  │ UART │  │ VGA  │  │ PS/2 │  │ BootROM │     │
│  │      │  │  FB  │  │ 键盘 │  │ (可选)  │     │
│  └──────┘  └──────┘  └──────┘  └─────────┘     │
└──────────────────────────────────────────────────┘
```

### 2.2 与真实 CPU 的关键差异

| 特性 | 真实 CPU (ARM M0/RV32I) | 本项目 |
|------|------------------------|--------|
| **时钟** | 1-3 GHz | 约 5-20 MHz (Verilator 模拟) |
| **架构** | 冯·诺依曼或哈佛+缓存 | 纯哈佛 (指令/数据存储器独立) |
| **流水线** | 3-7 级 | 单周期 (每周期完成一条指令) |
| **转发** | EX/MEM/WB → EX | 无（单周期不需要） |
| **缓存** | L1-I/D 各 32KB+ | 无，直接访问 BRAM |
| **分支预测** | 动态预测器 | 无（分支在下一条指令生效） |
| **乱序执行** | 现代 CPU 支持 | 不支持 |
| **虚拟内存** | MMU, TLB | 无 |
| **中断/异常** | 完整向量中断 | CSR + ecall/mret |
| **制程** | 3-7nm | Verilog 仿真 (Verilator) |

### 2.3 单周期数据通路

每条指令在一个时钟周期内完成全部操作。以 `sb` 为例：

```
posedge clk:
  1. PC 输出地址 → insn_mem 输出指令
  2. control 单元译码：reg_write=0, mem_write=1, alu_src=1, store_type=01
  3. regfile 读 rs1=t0, rs2=t1
  4. imm_gen 从指令中提取 12bit 符号立即数
  5. ALU: t0 + imm → 地址 alu_result
  6. data_mem: 地址 alu_result → 写入 store_data (rs2 的字节)
  7. (如需要) MMIO 路由: 如果地址在 0x40002xxx → vga_fb 写
  8. next_pc = pc + 4
```

每个硬件模块是纯组合逻辑 + 边沿触发寄存器。关键路径是：
```
PC → insn_mem → control/regfile/imm_gen → ALU → data_mem/vga_fb → (下一周期)
```

### 2.4 MMIO 地址映射（关键设计）

CPU 通过地址总线访问外设，无需特殊指令：

```
地址范围          硬件模块
───────────────  ──────────
0x0000_0000      指令存储器 (BRAM, 程序代码)
0x0000_1000      数据存储器 (BRAM, 全局变量/栈)
0x4000_0000      UART (串口通信)
0x4000_0004      UART RX 数据
0x4000_0008      UART 状态
0x4000_0030      PS/2 键盘
0x4000_2000      VGA 帧缓冲 (80×60 像素)
```

C 代码中的 `volatile unsigned char *FB = (unsigned char*)0x40002000` 使得 `FB[y*80 + x] = color` 被编译为普通 `sb` 指令，CPU 在访存阶段根据地址自动路由到 VGA 帧缓冲模块。

## 三、贪吃蛇的完整执行路径

### 3.1 从 C 代码到屏幕像素

```
snake_vga.c                    RISC-V GCC
──────────                     ─────────
FB[y*80+x] = 0xFF;     →      0x40002000 存入寄存器
                               y*80+x 计算偏移
                               sb 指令写字节

                    编译产物
                    ────────
                    snake_vga_code.hex  (机器码)
                    snake_vga_data.hex  (初始数据)

                    加载
                    ────
                    data_mem.sv: $readmemh("program.hex", mem)
                    insn_mem.sv: $readmemh("data.hex", mem)
```

### 3.2 一帧游戏的完整事件链

```
1. CPU 执行 init_game():
   ├── draw_border():
   │   └── 136 次 sb 指令 → 地址 0x40002xxx
   │       → MMIO 路由 → vga_fb.sv → fb[addr] = 0xFF
   └── 初始化 sx[], sy[], len=5, dx=1, dy=0

2. CPU 进入主循环 while(!over):
   ├── 清屏: 5 次 sb → fb[蛇旧位置] = 0x00 (黑)
   ├── 输入: lw 从 UART_STATUS (0x40000008)
   │   └── 有数据? 读 UART_RX → 'w'/'a'/'s'/'d'
   ├── 移动: ALU 计算新位置, 碰撞检测
   ├── 绘图: 6 次 sb → fb[食物新位置]=0xE0, fb[蛇身]=0x1C, fb[蛇头]=0xFC
   └── 延迟: for(d=0;d<1500;d++); → ~3000 addi+bnez 循环

3. Verilator C++ 模拟器 (sim_vga.cpp):
   ├── 驱动时钟: top->clk=1; top->eval(); top->clk=0; top->eval();
   ├── 注入按键: inj.send('w') → uart_rx_pin 按位翻转
   ├── 读取帧缓冲: top->vga_dbg_addr = y*80+x
   │   └── top->vga_dbg_data → uint8_t 像素颜色
   └── SDL2 渲染: 40×30 纹理 → 缩放到 640×480 窗口
```

### 3.3 时钟周期计时

一次游戏迭代约 3100 个 CPU 周期：

```
阶段              周期数    占比
────────────────  ──────   ────
draw_border       1000      (初始化一次)
清屏 (5 次 store)    25     0.8%
输入检查             10     0.3%
碰撞/移动            20     0.6%
绘图 (6 次 store)    30     1.0%
延迟循环           3000    96.7%
其它开销             15     0.5%
────────────────  ──────   ────
合计              ~3100    100%
```

### 3.4 物理信号流

```
Verilator 模拟循环:
┌──────────────────────────────────────────────────┐
│ C++ 代码                                         │
│                                                  │
│ top->clk = 1;   // 时钟上升沿                     │
│ top->eval();    // 计算所有组合逻辑                │
│   ├── PC → insn_mem → instr                      │
│   ├── control 译码                                │

```

## 四、与真实系统对比：为什么需要 Verilator 加速

| 仿真方式 | 速度 | 用途 |
|----------|------|------|
| Icarus Verilog (纯解释) | ~1 kHz | 小 testbench |
| **Verilator (编译为 C++)** | **~10 MHz** | **跑完整游戏** |
| Vivado XSim | ~100 kHz | FPGA 开发 |
| 真实 FPGA (如 Artix-7) | 50-100 MHz | 最终部署 |

Verilator 将 Verilog 编译为优化过的 C++，再编译为 x86 二进制。这个过程消除了 Verilog 解释开销，达到约 1000 倍加速——足够实时跑 640×480 的贪吃蛇。

## 五、关键设计决策回顾

1. **单周期而非流水线**：控制逻辑简单，无转发/阻塞/冲刷的调试负担，适合教学展示
2. **哈佛架构**：指令和数据存储器独立，避免结构冲突
3. **MMIO 而非专用 I/O 指令**：C 指针直接映射到外设，编译器无需特殊支持
4. **帧缓冲而非字符终端**：VGA 80×60 像素数组，比 UART 字符流更直观
5. **Verilator + SDL2 而非真实 FPGA**：开发迭代快（秒级编译），可用宿主键盘/屏幕
